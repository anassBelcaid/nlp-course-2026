Part I · The encoder bottleneck

Recall: one RNN reads, another writes

The encoder’s final hidden state becomes the decoder’s initial hidden state.

The whole source sentence reaches the decoder through one fixed-size vector, c.

This is the recurrent encoder–decoder architecture developed in the previous lecture (Sutskever et al. 2014; Cho et al. 2014).

One vector must remember everything

PAUSE · FIND THE LIMITATION When the decoder needs “demain,” what source representation can it inspect directly?

Early recurrent seq2seq models summarize a variable-length source with a fixed-dimensional context (Cho et al. 2014).

The bottleneck is not only storage—it is access

THE ONLY AVAILABLE PATH

\[p(y_t\mid y_{<t},\,\mathbf{c})\]

1 · COMPRESSEvery source detail competes for space inside the same vector.
2 · CARRYEarly information must survive every later encoder update.
3 · RECOVEREvery decoder step must reconstruct what it needs from c alone.

The decoder does not lack the source sentence—it lacks a direct way to retrieve the relevant part.

What if each decoder step could look back at all encoder states and choose where to focus?

Attention was introduced to replace the single fixed-context dependency with learned access to encoder states (Bahdanau et al. 2015).

Part II · Attention as soft lookup

Keep every source memory

Instead of asking the decoder to recover everything from \(c=h_4\), preserve all encoder states.

The decoder gains direct paths to earlier source representations—but it still needs a rule for choosing among them.

Attention lets each decoder step use the sequence of encoder states rather than only the encoder’s final state (Bahdanau et al. 2015).

Think of attention as a soft lookup

DECODER’S REQUEST

“Which source memory helps me generate tomorrow?”

At its core, attention is learned weighted averaging: a request is compared with stored representations, then the retrieved values are blended Stanford CS224N Lecture 5.

Turn compatibility scores into weights

GIVEN · DECODER STEP 4 We need to generate “tomorrow.” The model assigns one compatibility score to each source memory:

Le\(e_{4,1}=0.0\)
colis\(e_{4,2}=0.0\)

PAUSE · NORMALIZE THE SCORES

Apply softmax. What four attention weights do you expect—and what must they add up to?

\[ \alpha_{4,i}=\frac{\exp(e_{4,i})}{\sum_{j=1}^{4}\exp(e_{4,j})} \]

Additive attention normalizes alignment scores into a probability distribution over source positions (Bahdanau et al. 2015).

Softmax creates an attention distribution

\(\alpha_{4,i}\ge 0\) and \(\sum_i\alpha_{4,i}=1\)  →  the weights form a distribution over source positions.

Softmax preserves relative compatibility while turning arbitrary scores into nonnegative weights that sum to one Stanford CS224N Lecture 5.

Retrieve a weighted context

For visibility, suppose each encoder memory has only two coordinates:

Le\(h_1=[1,0]\)\(\alpha_{4,1}=0.10\)
colis\(h_2=[0,1]\)\(\alpha_{4,2}=0.10\)
arrivera\(h_3=[1,1]\)\(\alpha_{4,3}=0.20\)
demain\(h_4=[0,2]\)\(\alpha_{4,4}=0.60\)

\[ \begin{aligned} c_4 &= \sum_{i=1}^{4}\alpha_{4,i}h_i\\ &=0.10[1,0]+0.10[0,1]+0.20[1,1]+0.60[0,2]\\ &=\boxed{[0.30,\ 1.50]} \end{aligned} \]

Because “demain” receives the largest weight, its representation contributes most strongly—but the lookup remains soft and differentiable.

The attention context is the weighted sum of encoder states; the decoder uses a different context \(c_t\) at each target step (Bahdanau et al. 2015).

Attention repeats three operations

1SCOREHow compatible is the current request with each memory?\(e_{t,i}\)
→
2NORMALIZETurn all scores into a distribution.\(\alpha_{t,i}=\operatorname{softmax}(e_{t,i})\)
→
3RETRIEVEBlend memories using those weights.\(c_t=\sum_i\alpha_{t,i}h_i\)

One decoder step receives one task-dependent view of the source—not one universal sentence summary.

The mechanism is clear—but how does the model learn and compute the compatibility score \(e_{t,i}\)?

This score–normalize–retrieve abstraction is the common structure behind recurrent attention and later dot-product attention mechanisms (Bahdanau et al. 2015; Vaswani et al. 2017).

Part III · Cross-attention

Give the request and memories distinct roles

At decoder step 4, the model must match what it needs now against what each source position offers.

The decoder supplies the query; the encoder supplies the keys and values. Information crosses from source to target—hence cross-attention.

Cross-attention uses a target-side query with source-side keys and values Vaswani et al. (2017); Stanford CS224N Lecture 5.

One source state performs two jobs

ENCODER STATE

demain
\(h_4\)
MATCHING ADDRESS\(k_4=W_Kh_4\)Compared with the query“Is this memory relevant?”
RETRIEVABLE CONTENT\(v_4=W_Vh_4\)Added to the context if relevant“What information should I return?”

A key is used to decide the weight. A value is multiplied by that weight. They come from the same state, but they do different work.

The key–value terminology makes explicit the separation between addressing a memory and retrieving its content Vaswani et al. (2017); Alammar, The Illustrated Transformer.

PAUSE · CALCULATE FOUR SCORES

Compute \(e_{4,i}=q_4^\top k_i\). Which source key best matches the decoder’s request?

Dot-product attention measures query–key compatibility using an inner product (Vaswani et al. 2017).

The query selects a matching key

Le\([1,1]^\top[0,0]\)\(e_{4,1}=0.0\)
colis\([1,1]^\top[0,0]\)\(e_{4,2}=0.0\)
arrivera\([1,1]^\top[0.4,0.3]\)\(e_{4,3}=0.7\)
demain\([1,1]^\top[1.0,0.8]\)\(e_{4,4}=1.8\)

\[ [0.0,0.0,0.7,1.8]\xrightarrow{\text{softmax}}[0.10,0.10,0.20,0.60] \]

The large dot product does not retrieve \(k_4\). It only gives the position a large retrieval weight.

The dot products become logits; softmax converts them into attention weights (Vaswani et al. 2017).

Use the weights to retrieve values

Match against keys; retrieve from values. The highest-weight value contributes most to \(c_4\).

Attention output is a weighted sum of values, with weights determined by query–key compatibility (Vaswani et al. 2017).

Part IV · Self-attention

Keep the mechanism—change where the roles come from

CROSS-ATTENTION

target state→ querysource states→ keys + values

Two different sequences

SELF-ATTENTION

sequence states→ queriesthe same states→ keys + values

One sequence plays all three roles

QUERY · POSITION \(i\)\(q_i=W_Qx_i\)what token \(i\) is looking for
KEY · POSITION \(j\)\(k_j=W_Kx_j\)what token \(j\) can match
VALUE · POSITION \(j\)\(v_j=W_Vx_j\)what token \(j\) can return

Token \(i\) asks a question about the sequence; every token \(j\) offers a key to match and a value to retrieve.

Self-attention draws queries, keys, and values from the same sequence Vaswani et al. (2017); Stanford CS224N Lecture 5.

Which earlier token explains “it”?

Theanimalwastiredbecauseitran

To represent “it”, the model should combine the token itself with the context that identifies its referent.

PAUSE · CHOOSE THE USEFUL CONTEXT

If “it” sends one query to every token, which token should receive the largest attention weight? What information should come back?

Pronoun resolution is a standard intuition for contextual token representations in illustrated explanations of self-attention Alammar, The Illustrated Transformer.

One token performs a soft lookup

The output at position 6 is no longer a representation of “it” alone—it is “it” interpreted in this sentence.

Self-attention forms a contextual representation by taking a query-dependent weighted sum of values from the same sequence (Vaswani et al. 2017).

Every token asks its own question

Each position keeps its own output \(z_i\), but that output may contain information gathered directly from every other position.

Unlike recurrence, self-attention creates direct token-to-token paths and computes all position-wise lookups in parallel (Vaswani et al. 2017).

Stack the seven lookups into matrices

One row per token: \(X\in\mathbb{R}^{7\times d_{model}}\).

INPUTS\(X\)\(7\times d_{model}\)
× \(W_Q\)× \(W_K\)× \(W_V\)
QUERIES\(Q\)\(7\times d_k\)
KEYS\(K\)\(7\times d_k\)
VALUES\(V\)\(7\times d_v\)
ALL QUERY–KEY SCORES\(S=QK^\top\)\(7\times7\)
ROW-WISE NORMALIZATION\(A=\operatorname{softmax}(S)\)each row sums to 1
ALL CONTEXTUAL OUTPUTS\(Z=AV\)\(7\times d_v\)

Row \(i\) of \(A\) contains the attention weights produced by token \(i\)’s query. Row \(i\) of \(Z\) is that token’s retrieved context.

Matrix multiplication computes every pairwise query–key score and every weighted value sum efficiently Vaswani et al. (2017); Alammar, The Illustrated Transformer.

One learned connection can link distant tokens.

TWO QUESTIONS REMAIN How do we stop a language model from looking into the future? Can one similarity pattern capture every useful relationship?

Self-attention provides constant-length paths between positions, while its unrestricted all-to-all form introduces modeling and computational questions (Vaswani et al. 2017).

Larger vectors can create overconfident scores

A few large logits can push the distribution close to \(0\) or \(1\).

When softmax saturates, its gradients become small. We need the score scale to remain controlled as the key dimension grows.

Scaled dot-product attention compensates for growing dot-product magnitude at larger key dimensions (Vaswani et al. 2017).

A single distribution can mix these signals. Multiple heads let the model perform several different lookups in parallel.

Head interpretations are illustrative rather than guaranteed; multi-head attention provides separate learned projection spaces (Vaswani et al. 2017).

Each head has its own \(W^Q\), \(W^K\), and \(W^V\). Their outputs are combined into one representation per token.

Multi-head attention projects queries, keys, and values several times, applies attention in parallel, then concatenates the results (Vaswani et al. 2017).

The same sentence can be viewed in several ways

The animal did not cross the street because it was wide.

The heads do not receive different sentences. They learn different projections of the same input, retrieve different evidence, then combine their results.

Without positional information, self-attention is permutation equivariant: reordering inputs only reorders outputs (Vaswani et al. 2017).

Attention mixes positions—not features deeply

Attention answers “which positions should exchange information?” A complete layer must also answer “how should each position transform what it received?”
